## 3. 호스팅 구조 (중요)

```
사용자 브라우저
     │
     ▼
Render 웹 서비스 (Flask + gunicorn)   ← 코드: GitHub main 브랜치 자동 배포
     │  DATABASE_URL 환경변수로 연결
     ▼
Neon PostgreSQL (데이터 저장소)        ← 물품·부서원·대여기록
```

- **GitHub `main` 브랜치에 push하면 Render가 자동 재배포** (2~3분 소요)
- 무료 플랜은 미사용 시 절전 → **첫 접속이 최대 50초 지연** (정상)

### 환경변수 (Render 대시보드 → equipment-rental → Environment 탭)
| 키 | 용도 | 비고 |
|----|------|------|
| `DATABASE_URL` | Neon 연결 주소 | 비밀번호 포함, 절대 소스에 커밋 금지 |
| `ADMIN_PIN` | 관리자 PIN | |
| `TELEGRAM_BOT_TOKEN` | 대여/반납 알림 봇 | 선택 |
| `TELEGRAM_CHAT_ID` | 알림 수신 대화방 | 선택 |

> ⚠️ **`render.yaml` 주의**: 과거 Render 무료 DB가 삭제되면서 `DATABASE_URL`을 Blueprint에서 분리(`sync: false`)했습니다. 이 값은 **Render 대시보드에서 직접** 관리하며, `render.yaml`에 DB를 다시 묶으면 안 됩니다.

## 4. 로컬에서 실행하기

```bash
cd equipment-rental
pip install -r requirements.txt
```

`.env` 파일을 만들고 (이 파일은 `.gitignore`로 커밋 안 됨):

```
ADMIN_PIN=원하는PIN
# DATABASE_URL 을 넣으면 Neon(운영DB) 사용, 비우면 로컬 SQLite(rental.db) 사용
# DATABASE_URL=postgresql://...  ← 운영 데이터로 테스트할 때만, 끝나면 제거
```

```bash
python app.py        # http://localhost:5000
```

- **DATABASE_URL이 없으면 자동으로 로컬 SQLite** 사용 → 운영 데이터 안전
- 운영 DB로 화면 확인이 필요하면 `.env`에 `DATABASE_URL`을 임시로 넣고, 끝나면 반드시 제거

## 6. 데이터 모델 (PostgreSQL / SQLite 공용)

- **items**: `id, name, type, sort_order, maintenance_from, maintenance_until`
  - `maintenance_*` = 고장 수리 기간 (있으면 해당 기간 예약 차단)
- **rentals**: `id, item_id, borrower_name, rented_at, due_date, returned_at, cancelled_at`
  - `returned_at` 값 있으면 반납완료 / `cancelled_at` 값 있으면 취소(소프트 삭제)
- **users**: `id, username, password_hash, display_name`

> `db.py`의 `init_db()`가 앱 시작 시 테이블 생성 + 누락 컬럼 마이그레이션을 수행합니다. **새 빈 DB면 기본 물품 5개를 자동 등록**합니다.

## 7. 주요 기능

### 일반 사용자
- 물품별 **대여신청**(대여일·반납일 선택, 오늘~31일 범위)
- 날짜 겹침·본인 중복 신청·수리 기간 **예약 차단**
- 내 대여 현황 / 반납 / 취소
- **이번 주 장비별 대여현황** 표, **달력 보기**(FullCalendar)
- **대여 이력**(본인 것만)

### 관리자 (PIN 로그인)
- 대시보드: 당일 현황 + 물품별 월별 대여일수(+엑셀)
- 물품 관리: 추가·순서변경·삭제, **고장 수리 기간 설정/해제**
- 대여 관리: 직접 등록·강제 반납·필터·엑셀·삭제
- 부서원 관리: 명단 일괄 등록, 계정 추가·비번 초기화·삭제
- 달력 보기 / **백업·복원**

## 8. 백업 / 복원 (데이터 유실 대비 — 매우 중요)

- 관리자 모드 → **💾 백업 / 복원**
  - **백업**: 물품·부서원·대여기록 전체를 JSON 1개 파일로 다운로드 → 개인 PC/사내 드라이브 보관
  - **복원**: 백업 JSON 업로드 → 없는 것만 추가(중복 안전, 여러 번 올려도 OK)
- **권장: 매달 1회 백업 파일 다운로드 보관**
- 진단용 `/health/db` 접속 시 백엔드·연결·행수 확인 가능

## 9. 과거 장애와 교훈 (반드시 숙지)

1. **Render 무료 PostgreSQL이 삭제됨** → 호스트 이름이 DNS에서 사라져 전체 500 에러
   - 원인: 무료 DB는 일정 기간 후 자동 삭제
   - 조치: **Neon(만료 없음)으로 이전**. 이후 같은 일 재발 안 함
   - 교훈: DB는 만료 없는 서비스를 쓰고, 정기 백업 필수
2. **달력이 안 보임**: 브라우저 캐시 / `/api/events` 권한 문제였음 → 해결 완료
3. **대여 기록 복원**: 당시 백업이 없어 텔레그램 알림 캡처로 일부만 복구 → 백업 습관의 중요성

## 10. 보안 주의사항 (인수 즉시 확인)

- **Neon DB 비밀번호 교체 권장**: 과거 작업 중 연결 주소가 노출된 적이 있음
  - Neon 콘솔 → 프로젝트 → **Roles** → `neondb_owner` → **Reset password**
  - 새 연결 주소를 Render `DATABASE_URL`에 다시 입력
- `.env`, 비밀번호, 토큰, 연결 주소는 **절대 GitHub에 커밋 금지** (`.gitignore`로 제외됨)
- 백업 JSON에는 부서원 계정(해시)이 들어 있으니 외부 공유 금지

## 12. 새 DB로 이전해야 할 때 (Neon 등)

1. Neon(neon.tech) 가입 → 프로젝트 생성 (Region: Singapore 권장)
2. Connection string 복사 (`postgresql://...?sslmode=require`)
3. Render → Environment → `DATABASE_URL` 교체 → Save (자동 재배포)
4. 접속 후 물품 5개는 자동 생성, 부서원은 "명단 일괄 등록" 또는 백업 복원
5. `/health/db` 로 `connect: OK` 확인

> 코드는 `postgres://`/`postgresql://` 스킴 차이, `sslmode`, 절전 깨우기 재시도를 자동 처리하므로 **연결 주소만 바꾸면** 됩니다.
