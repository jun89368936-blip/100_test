# PRD — 부서 공유 물품 대여 관리 시스템

> **문서 유형:** Product Requirements Document (제품 요구사항 정의서)
> **작성일:** 2026년 6월
> **버전:** 1.0
> **Product Owner:** 물산업부문 담당자

---

## 1. 배경 및 문제 정의

### 1.1 현재 상황 (AS-IS)

물산업부문에는 부서원 253명이 공유하는 드론 3대, 노트북 2대가 있다.
현재는 대여 현황을 수기 메모 또는 구두 확인에 의존하고 있다.

### 1.2 핵심 문제

| # | 문제 | 영향 |
|---|------|------|
| P1 | 누가 어떤 물건을 빌려갔는지 실시간 확인 불가 | 이중 대여 발생 |
| P2 | 반납 예정일 관리 안 됨 | 장기 미반납으로 다른 팀원이 사용 못함 |
| P3 | 대여 이력이 남지 않음 | 분실·파손 시 책임 소재 불분명 |
| P4 | 관리자가 현황 파악하려면 직접 물어봐야 함 | 관리 비효율 |

### 1.3 해결 목표 (TO-BE)

- 언제 어디서든 스마트폰·PC로 대여 현황 확인 및 신청 가능
- 미반납·연체 발생 시 즉시 인지
- 관리자 없이도 부서원이 자율적으로 대여·반납 처리
- 대여 이력이 자동으로 기록·보관

## 2. 목표 및 성공 지표

### 2.1 제품 목표

> "물품 대여 요청부터 반납 확인까지 모든 과정을 1분 이내에 완료할 수 있는 셀프서비스 플랫폼"

### 2.2 성공 지표 (KPI)

| 지표 | 현재 | 목표 |
|------|------|------|
| 이중 대여 발생 건수 | 월 평균 N건 | **0건** |
| 대여 처리 소요 시간 | ~5분 (담당자 확인 후) | **1분 이내** |
| 장기 미반납(7일+) 비율 | 불명 | **5% 이하** |
| 관리자 수동 개입 건수 | 매 대여마다 | **비정상 상황에만** |

## 3. 사용자 (Who)

### 3.1 페르소나

#### 페르소나 A — 일반 부서원 (주 사용자)
- **이름:** 김현장 (사번 214047)
- **상황:** 현장 출장 전날 드론이 필요함. 지금 빌릴 수 있는지 확인하고 싶음.
- **목표:** 드론이 사용 가능한지 확인 → 빠르게 예약 → 반납일 잊지 않기
- **불편함:** 담당자에게 전화해야 하는 번거로움, 다른 팀원이 가져간 줄 몰랐던 경험

#### 페르소나 B — 관리자 (주 1회 이상 사용)
- **이름:** 이관리 (물품 담당자)
- **상황:** 드론이 어디 있는지, 누가 얼마나 쓰는지 파악이 안 됨
- **목표:** 전체 현황 한눈에 파악, 비정상 상황(연체) 즉시 인지, 물품 추가/삭제
- **불편함:** 이력 없이 분실 발생 시 책임 소재 불분명

## 4. 사용자 스토리 (User Stories)

### 4.1 일반 사용자

| ID | 사용자 스토리 | 우선순위 |
|----|--------------|---------|
| US-01 | 나는 **로그인 없이** 누구나 접근하면 안 되므로, 사번+비밀번호로 로그인하고 싶다. | 🔴 Critical |
| US-02 | 나는 **지금 빌릴 수 있는 물품**이 무엇인지 메인 화면에서 즉시 확인하고 싶다. | 🔴 Critical |
| US-03 | 나는 **대여 신청 시 이름을 직접 입력하지 않고** 로그인 계정에서 자동으로 적용되길 원한다. | 🔴 Critical |
| US-04 | 나는 **대여 기간(시작일~반납일)을 지정**해서 미리 예약하고 싶다. | 🔴 Critical |
| US-05 | 나는 **내가 현재 빌린 물품**을 메인 화면 상단에서 바로 확인하고 싶다. | 🔴 Critical |
| US-06 | 나는 **반납 예정일이 지난 경우** 빨간색 경고로 인지하고 싶다. | 🟠 High |
| US-07 | 나는 **달력 화면**에서 전체 대여 일정을 한눈에 보고 싶다. | 🟠 High |
| US-08 | 나는 **대여 이력**을 조회하고 필요시 엑셀로 다운로드하고 싶다. | 🟡 Medium |
| US-09 | 나는 **초기 비밀번호(사번)를 변경**해서 개인 비밀번호를 설정하고 싶다. | 🟡 Medium |

### 4.2 관리자

| ID | 사용자 스토리 | 우선순위 |
|----|--------------|---------|
| US-10 | 나는 **관리자 전용 PIN**으로 별도 로그인하여 관리 기능에 접근하고 싶다. | 🔴 Critical |
| US-11 | 나는 **대시보드**에서 전체 물품 수·대여 현황·연체 현황을 한눈에 보고 싶다. | 🔴 Critical |
| US-12 | 나는 **물품을 추가·삭제**하고 메인 화면에서의 **표시 순서를 직접 조정**하고 싶다. | 🟠 High |
| US-13 | 나는 **253명 부서원 계정을 버튼 한 번으로 일괄 등록**하고 싶다. | 🟠 High |
| US-14 | 나는 **비밀번호를 잊은 부서원의 비밀번호를 초기화**해줄 수 있어야 한다. | 🟠 High |
| US-15 | 나는 **대여 기록을 강제 반납 처리하거나 삭제**할 수 있어야 한다. | 🟡 Medium |
| US-16 | 나는 **대여·반납 이벤트 발생 시 텔레그램 알림**을 받고 싶다. | 🟡 Medium |

## 6. 비기능 요구사항

| 항목 | 요구사항 |
|------|---------|
| **가용성** | 평일 업무 시간(08:00~18:00) 99% 이상 접근 가능 |
| **응답 속도** | 일반 페이지 로딩 3초 이내 |
| **보안** | 비밀번호 단방향 해싱, 미인증 접근 차단 |
| **호환성** | Chrome/Edge/Safari 최신 버전, 모바일 브라우저 |
| **비용** | 무료 호스팅 유지 (Render.com Free Tier) |
| **유지보수** | 관리자 비개발자도 물품·계정 관리 가능 |

## 7. 제약 조건

| 제약 | 설명 |
|------|------|
| **서버 리소스** | Render 무료 플랜 → 비활성 15분 후 슬립 (UptimeRobot + self-ping으로 방지) |
| **Shell 접근 불가** | Render 무료 플랜 Shell 미제공 → 초기 데이터 등록은 앱 내 버튼으로 처리 |
| **비밀번호 열람 불가** | 단방향 해싱 정책 → 관리자도 기존 비밀번호 확인 불가, 초기화만 가능 |
| **DB 용량** | PostgreSQL 무료 플랜 1GB 제한 |
