도시계획시설결정 입안서류 자동작성기 — 진행 기록
====================================================

목표(사용자 말): 설계 보고서와 현황분석 보고서를 등록하면 입안서류 전체를 자동으로 만든다.
범위 확정: 전체(표지·입안서·목차·Ⅰ~Ⅷ·환경/교통/경관성 검토서). 출력 HWPX. 로컬 앱.
(출력형식·실행형태·시설종류는 사용자가 답하지 않아 기본값으로 진행: HWPX / 로컬 웹앱+bat / 수도 중심+하수 용어팩)

탐색에서 확인한 것 (2026-10-21)
- 샘플: 인허가/도시계획 시설결정 입안신청서_교동삼산.pdf = 358쪽 완성본(사용자: "샘플").
  구성: 표지 → 입안서(입안사유·내용·기대효과) → 목차 → Ⅰ 결정(안)(조서·사유서·결정도)
  → Ⅱ 계획의 개요 → Ⅲ 상위·관련계획 → Ⅳ 현황 → Ⅴ 배수시설 조성계획 → Ⅵ 기초자료(환경·교통·경관성)
  → Ⅶ 편입토지조서·토지대장 → Ⅷ 설계도.
- 인허가/도시계획시설결정/*.hwp = 같은 패키지의 장별 원본(HWP). 환경성(50쪽)·경관성(56쪽)·교통성(60쪽) 검토서는
  입안서의 사업개요·결정조서·사유서를 그대로 되풀이한다 → 사업 사실을 한 번 뽑아 전 문서에 재사용하는 구조.
- 교통성 검토서는 외부 교통 용역사가 교통량 조사·서비스수준 분석을 해서 만든다(교동배수지.pdf/삼산배수지.pdf)
  → 보고서에 없는 조사 결과는 만들 수 없다. [외부 자료 필요]로 표시한다.
- 샘플 PDF 자체에 숫자 불일치가 있다: 교동 면적 9,806(입안서) vs 19,341(조서), 삼산 10,502/10,965/10,014,
  소유자별 집계 합계 6,751(≠19,341), 지목별 비율 6.4/93.6%(실제 1.5/98.5%) → 일관성 점검 기능이 가치 있음.
- 실제 입력 후보: DIDAS DATA/나의 프로젝트/교동·삼산배수지…/실시설계/성과품 취합/보고서/…/제1장 총론(수정중).hwp
  (설계보고서 1장만 존재). 다른 프로젝트 군남면 계획배수지 연천실시-1장 총론.hwp 로 일반화 시험.

기술 검증(스파이크)
- kordoc 4.24.0 npm 라이브러리: parse(ArrayBuffer)→{blocks,images,markdown,outline,pageCount}. 66쪽 HWP 0.4초.
  제목 레벨·표·이미지(바이트 포함)·쪽번호(layout) 복원됨.
- markdownToHwpx(md,{images,page}) → validateHwpx ok. renderDocument(…,{format:'png',pages}) 로 쪽 이미지 확인 가능.
  재생성 결과는 원본 HWP보다 서식이 단순(굴림체 본문, 평이한 제목) — 초안 용도로 충분, 한글에서 다듬는 전제.
- 90MB HWP(05장) → 112MB HWPX. 이미지 원본이 크다. 크기 경고 필요.
- Python 에 python-docx 없음(docx 경로 미사용). kordoc 는 npx 로도 MCP 서버로 돈다(내 MCP 도구와 동일 엔진).

  report.hwpx(입지검토서: ①사업개요 ②지형지세 ③생태·자연환경 ④토지이용 ⑤토지이용규제 ⑥건축물 ⑦공법제한 ⑧도시및주거환경),
  1_estate_list.xlsx(시트 '편입 토지'178행·'미편입 인근토지'·'편입 건축물'·'미편입 인근건축물') = 편입토지조서 입력원,
  data/*.shp = GIS 레이어(사용하지 않음). 한컴 전용 글리프(U+F02B1~)로 쓴 원문자 장 제목에 주의.

  →인문환경(지목별·소유별·도시관리계획 지정)→현황종합). 시설마다 현황분석 보고서·필지 엑셀을 따로 등록하는 구조가 필요.
