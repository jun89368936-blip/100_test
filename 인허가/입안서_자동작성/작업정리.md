# 도시계획시설결정 입안서류 자동작성기 — 작업 정리

작성: 2026-10-22 (US-007 완료 시점으로 갱신) · 작업 폴더: `인허가/입안서_자동작성/`

## 1. 만들려는 것

설계 때 도시계획시설결정을 자주 하는데 입안서류 작성에 시간이 오래 걸려서, **설계보고서와 현황분석 보고서를 등록하면 입안서류 전체를 자동으로 만들어 주는 프로그램**.
사용자 설명: 입안서류의 내용은 보통 설계보고서·현황분석 보고서를 쓰면 거의 들어 있는 내용이다. 범위는 **전체**(검토서 포함).

사용자가 답하지 않아 제가 정한 기본값(틀리면 바로잡아 주세요):

| 항목 | 기본값 |
| --- | --- |
| 출력 형식 | HWPX (한글에서 열어 수정) — 장별 파일 + 점검표 |
| 실행 형태 | 로컬 웹앱(127.0.0.1) + 실행.bat |
| 시설 종류 | 수도공급설비(배수지 등) 중심, 하수 계열은 용어 팩만 |
| AI 사용 | 없음(규칙 기반) — PC에 Claude API 키가 없음 |

## 2. 입력 자료에서 알게 된 것

### 샘플 입안서 (정답 비교용)
- `인허가/도시계획 시설결정 입안신청서_교동삼산.pdf` — 358쪽 완성본. 사용자 말씀: "샘플".
- 구성: 표지 → 입안서(입안사유·내용·기대효과) → 목차 → Ⅰ 결정(안)(조서·사유서·결정도) → Ⅱ 계획의 개요 → Ⅲ 상위·관련계획 → Ⅳ 현황 → Ⅴ 배수시설 조성계획 → Ⅵ 기초자료(환경·교통·경관성 검토서) → Ⅶ 편입토지조서·토지대장 → Ⅷ 설계도.
- `인허가/도시계획시설결정/*.hwp` — 같은 패키지의 장별 원본. 환경성(50쪽)·경관성(56쪽)·교통성(60쪽) 검토서가 입안서의 사업개요·결정조서·사유서를 그대로 되풀이 → 사업 사실을 한 번 뽑아 전 문서에 재사용하는 구조.
- **샘플 PDF 자체의 숫자 오기** (앱은 계산값을 쓰고 불일치를 점검표에 올려야 함)
  - 시설면적: 교동 9,806(입안서) vs 19,341(조서) · 삼산 10,502 / 10,965 / 10,014
  - 소유자별 집계 합계 6,751(≠19,341), 지목별 비율 6.4/93.6%(실제 1.5/98.5%)
  - 삼산 지목별: '도'(725㎡)를 '전'에 합쳐 '전 2필지 946㎡'로 집계(실제 도 725 / 임 10,019 / 전 221)

### 사용자가 넣어 준 입력 (2026-10-21)
- `인허가/설계보고서/` — 교동·삼산 설계보고서 1~7장(완) HWP. 1장의 총사업비는 18,127백만원(수정중 본은 19,115) → 보고서 버전에 따라 값이 바뀜. 표지에 다른 사업 문구("화도배수지")가 남아 있음.
- `인허가/현황분석 보고서/` — 사용자의 GIS 현황분석 도구 산출물. **이 지역 보고서가 없어 다른 지역(전남 여수시 화정면 여자리)을 샘플로 넣음.**
  - `report.hwpx` 입지검토서: ①사업개요 ②지형지세 ③생태·자연환경 ④토지이용 ⑤토지이용규제 ⑥건축물 ⑦공법제한 ⑧도시및주거환경
  - `1_estate_list.xlsx` 필지 목록 — 시트 '편입 토지'(178행)·'미편입 인근토지'·'편입 건축물'·'미편입 인근건축물' → 편입토지조서의 입력원
  - `data/*.shp` GIS 레이어 — 사용하지 않음
- 샘플 입안서 Ⅳ.3 "계획대상지 현황분석"은 현황분석 보고서를 시설별로 재배열한 것(광역입지 → 자연환경(표고·경사·생태자연도) → 인문환경(지목별·소유별·도시관리계획) → 현황종합). 시설마다 현황분석 보고서와 필지 엑셀을 따로 등록하는 구조가 필요.

### 만들 수 없는 것 (보고서에 없으면 빈칸을 숨기지 않고 표시)
교통량 조사·서비스수준 분석(샘플도 외부 교통 용역사가 작성), 조망점 사진·시뮬레이션, 토지대장 원본 → `[외부 자료 필요]` / `[작성 필요]`로 표시하고 점검표에 모은다.

## 3. 기술 검증 결과

- kordoc 4.24.0 npm 라이브러리로 읽기·쓰기 모두 가능: `parse`(제목·표·이미지 바이트·쪽번호), `markdownToHwpx`(이미지 임베드), `validateHwpx`, `renderDocument`(PNG 확인). 66쪽 HWP를 0.4초에 읽음.
- 재생성한 HWPX는 원본 HWP보다 서식이 단순(초안 용도 — 한글에서 다듬는 전제). 90MB HWP → 112MB HWPX로 이미지가 커서 크기 경고가 필요.
- 한컴 전용 글리프(U+F02B1…)로 저장된 원문자(①②…)·목차 나열·연혁 목록 줄 등 실제 문서의 잡음을 처리하도록 제목 복원기를 보정함.

**입력 자료 변경(2026-10-22):** `인허가/현황분석 보고서/` 가 교동배수지 보고서로 바뀌었다(상용리 산3번지 일원 6,102㎡, 편입 10필지). 예전 여수 샘플은 `다운로드\송여자도` 에 같은 파일이 있어 시험은 그쪽을 읽는다. 교동 보고서는 표고·경사 값이 0 이다(강화도 북쪽이라 DEM 이 없는 것으로 보임) → Ⅳ장은 0 표 대신 `[작성 필요]`. 사용자 결정에 따라 교동 편입토지는 새 필지 엑셀(10필지 6,197㎡)을 쓰고 삼산은 샘플 표(10,965㎡)를 쓴다 — 전 장의 교동 면적이 6,197㎡ 로 바뀌었다.

**작업 방식(2026-10-22 사용자 요청):** 목차부터 만들고 한 장씩 완성한다. 진행은 `chapters.json`(대기/작업중/완료)에, 장 조립기는 `src/compose/chapters/` 에 하나씩 등록한다. `npm run preview`(http://127.0.0.1:4173)를 띄워 두면 파일을 저장할 때마다 자동으로 다시 조립해 브라우저에 바로 보인다. 아직 조립기가 없는 장은 '들어갈 재료'(배정된 원본 절·문안·`[작성 필요]`)가 보인다.

**스토리별 핵심 결과**
- US-004: 편입면적 열을 열 순서가 아니라 우선순위(최종편입 > 편입면적 > 편입구적)로 골라 여수 엑셀 178필지 집계가 시트 값과 일치.
- US-005: 조서 첫 행 `신설|①|수도공급설비(교동배수지)|강화군 교동면 상용리 산4번지 일원|-|증)19,341|19,341|-`. 면적은 편입토지 합계를 쓰고, 보고서 값(9,806 등)과 다르면 경고.
- US-006: 설계보고서 1~7장 → 입안서 절 자동 배정. 상위계획 검토·관련법규·인문사회·건축/부문별 계획은 설계보고서에 대응 절이 없어 미배정(→ US-007 라이브러리 문안이나 [작성 필요]).
- US-007: 문안 라이브러리(입안사유·기대효과 7항목·계획의 목적·범위·수립절차·관련법규 요지·상위계획 일반론)를 `{{변수}}` 로 저장. 설계보고서 '과업의 목적'에서 상위계획명·기존 배수권역을 찾아 채우고, '사업의 효과'·'과업의 목적' 절이 있으면 그 문장을 먼저 쓴다. 채우지 못한 변수는 `[작성 필요: 변수명]`. 샘플 PDF 입안사유와 문장 단위로 일치함을 시험으로 확인.

**US-007 알려진 한계**
- 입안사유의 '급수지역'(예: 강화도)과 수립절차의 '입안기관'은 보고서에서 찾을 수 없어 화면에서 입력해야 한다.
- 샘플 입안사유의 상위계획 문구(「2040 수도정비 기본계획」·「2045 수도정비 기본계획(변경)」)는 설계보고서 표기(「2040 인천 수도정비기본계획」 등)와 달라, 자동값은 설계보고서 표기를 따른다.
- 관련법규 검토의 개발행위규모·소규모환경영향평가 판정은 용도지역별 면적이 있어야 해서 `[작성 필요]`. 재해영향평가(5천㎡ 이상)만 자동 판정. 법령은 요지만 적었으므로 원문 확인 필요.
- 하수 문안 팩은 샘플이 없어 '샘플 미검증'으로 표시되고 모든 문안이 검토 필요.
